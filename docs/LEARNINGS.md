# meeting_ai team learnings

System-level lessons every agent must know. Read before starting; **append a dated bullet whenever something cost you time** — not facts (those go in `PROJECT-CONTEXT.md`) but "what to check first next time".

## 2026-09-16 — bootstrap
- The owner's Windows console is code page cp874. `python -m meeting_ai …` crashes with `UnicodeEncodeError: 'charmap' codec` on the first Thai character. Always run through `./mai` / `.\mai.cmd` (they export `PYTHONIOENCODING=utf-8`) or set `PYTHONIOENCODING=utf-8` / `PYTHONUTF8=1` yourself. Check this first when a "crash" only reproduces from a raw `python` call.
- `.gitignore` ignores `*.json` globally. A new JSON file you expect to commit (fixtures, configs) silently stays untracked until you add a `!path/to/file.json` exception, as done for `vercel.json` and `.claude/agent-team.json`.
- `whisper-cli` and the ggml model are not installed on the dev machine, so any `process` job fails after upload. Test routing, permissions and validation with the in-process recipe in `PROJECT-CONTEXT.md` and monkeypatch `runner.transcribe_job`; do not spend time "fixing" transcription locally.
- `git status` in this repo runs inside a worktree under `.claude/worktrees/` on branch `claude/…`. The agent team files were generated there; `project_root` in `.claude/agent-team.json` points at the main checkout (`C:/project/meeting_ai`), so re-running `render.py` from a worktree needs `--out <worktree path>` or it writes into the main checkout.
- The `agent-team` skill's `render.py` uses default file encodings and `os.path.relpath`: on Windows run it with `PYTHONUTF8=1` and expect backslash doc paths that need normalizing to `/` (done once during bootstrap).

## 2026-09-16 — P0 fix round (consolidated from backend-dev ×3, test-engineer, code-reviewer, security-engineer)
- `meeting_ai/web/jobs.py:28` does `from .backend import cloud, store` — a **frozen copy**. Simulating cloud mode needs FIVE patches: `backend.cloud`, `backend.store`, `jobs.cloud`, `jobs.store`, `server.store`. Patching `backend.cloud` alone flips `auth_required()` but leaves `jobs` on the file store.
- `jobs.draft(mid)` in cloud mode is `store.job_get(mid)["_spec"]` for a job of ANY status (done/running included). It is not "a draft". Any permission or upload logic built on "a draft exists" must check `job["status"] == "draft"` explicitly.
- `submit_summarize` uses job id == meeting id and `job_upsert … on conflict do update set spec = excluded.spec`: whoever may re-summarize rewrites the whole spec row. Ask "who can call this with `self.user_id is None`?" — share-edit visitors can, and they silently dropped `owner_id` until the owner-fallback fix.
- Never compare `spec.get("owner_id") == self.user_id` directly on a path a share-only visitor can reach: `None == None` is True. Use `if owner and owner == self.user_id` (pattern in `_may_write_job`).
- psycopg passes `None` untyped; write `%s::text is null` (precedent: `job_claim` uses `%s::text[]`) or Postgres raises "could not determine data type of parameter".
- SQL can be proven without a database: monkeypatch `pgstore.db.connect` with a fake context manager that records `(sql, params)`; assert placeholder count == len(params) and the expected fragments. Catches ordering bugs instantly.
- When a path is shared and mutable, the bugs "reads someone else's file" and "deletes someone else's file" come together — `_keep_debug_shot()` unlinks its sources, so a shared `/out` turned it into an evidence shredder. Check both whenever you see a shared dir.
- Release the mount before touching the path: `docker rm -f` BEFORE `rmtree`, `_prune_stages` AFTER the `docker stop` loop — and `bot._run()` swallows timeouts (`_Timeout`, rc 124), so "after stop" is not an invariant. Confirm with `docker ps` before deleting anything a container might still mount.
- The bot's WAV destination in worker/web mode is a `tempfile.TemporaryDirectory` on another filesystem (Ubuntu `/tmp` is often tmpfs): `shutil.move` is copy+unlink and can fail (ENOSPC, AV lock). Never delete the staging dir in a `finally` unless the move succeeded or the dir holds no non-empty WAV.
- A `finally` written "to keep the folder tidy" deletes irreplaceable data more often than you think. Enumerate every exception path and what is in the folder at that moment before adding cleanup.
- Fixing the list endpoint is not fixing the leak: `workers_list()` joins `jobs.title` and still served every tenant's titles through `/api/jobs` and `/api/workers`. Grep for the leaking FIELD, not just the route.
- Adding a read-side twin (`_may_read_job`) exposed that the write-side original (`_may_write_job`) used `job["id"]` where a translate job id is not a meeting id. When you add a twin, diff it against the original line by line.
- `config.py` evaluates env into class attributes at import and loads `.env` with `setdefault`; tests that change `STT_PROVIDER`/`STT_API_KEY` must set env BEFORE `import meeting_ai` (or run a subprocess). Provider routing is testable without whisper by patching `stt.local_available` / `stt.resolve`.
- `store.py` computes `INDEX_PATH` and `SETTINGS_PATH` from `WEB_DIR` once at import: patching `store.WEB_DIR` alone still writes the owner's real `index.json`. Patch all three (done in `tests/_harness.py`).
- Several agents editing one worktree concurrently: a bare `git diff --stat` includes everyone's work. Always scope with `git diff --stat -- <your files>` before reporting.
- `$TMPDIR` is empty in Git Bash on this machine (`"$TMPDIR/x"` → `/x` → permission denied). Use the absolute scratchpad path. Long heredocs (> ~5 KB) get truncated by the Bash tool — write a script file first, then run it.
- `Path.glob()` on a missing directory does not raise in Python 3.12 but has changed between versions; keep the explicit `try/except OSError`.

## 2026-09-16 — api-tester run: `.env` has live R2 credentials, file mode is NOT storage-isolated

## 2026-09-16 — e2e-tester run: job lifecycle observability + worker-loop harness
- `GET /api/jobs` returns **only `queued`/`running`** jobs in both modes (`jobs.active()` filter, `pgstore.job_active` `where status in ('queued','running')`). A job that fails **disappears from the list** instead of showing up as `status: "error"` — the browser survives this because `app.js` re-fetches `GET /api/jobs/{id}` for ids that vanished (`app.js:453-460`), but any script/integration that polls only the list will sit there until its own timeout and never see the error. Poll the list, then always fetch by id when an id disappears.
- `GET /api/meetings/{id}` returns `segments` as an **integer count** (from the index metadata) and the actual array as `segments_list`; `transcript` is the rendered text. Asserting `len(resp["segments"])` blows up with `TypeError: object of type 'int' has no len()`.
- A full **remote-worker loop can be exercised without Postgres**: file mode + `REMOTE_WORKER=1 WORKER_TOKEN=<random>` + plain HTTP to `/api/worker/{heartbeat,claim}` and `/api/worker/jobs/{id}/{tracks/mixed,progress,audio,result,error}`. `claim` returns `204` with an empty body when the queue is empty, and the stop flag really does come back in the `progress` response after `POST /api/jobs/{id}/stop`.
- Unvalidated `lang` in `POST /api/meetings/{id}/translate` is not cosmetic: the job id becomes `<mid>.tr.<lang>` and `/api/worker/jobs/{job_id}/audio` builds `store.WEB_DIR / f"{job_id}.{ext}"` with **no `valid_id()`** — with the id percent-encoded in the URL (`%2F`, so path splitting doesn't eat it) a `WORKER_TOKEN` holder writes the body to an arbitrary path. Reproduced on an isolated instance; see the e2e report / BACKLOG. When a user-supplied string reaches an identifier, follow that identifier into every path built from it.

## 2026-09-16 — code-reviewer: `$` in a Python regex is not `end of string`
- Every id/path validator in this repo is `re.match(r"^...$", value)` (`store.valid_id`, `pgstore.valid_id`, and the new `server._safe_job_id`). Python's `$` also matches **just before a trailing newline**, so `store.valid_id("20260916-120000-abcdef" + chr(10))` returns `True` (verified 2026-09-16). Ids become filenames (`WEB_DIR / f"{job_id}.{ext}"`) and a newline is a legal POSIX filename character. Use `re.fullmatch` (or the `\Z` anchor) in new validators, and always test a valid value with a trailing newline appended when you write or review one. NUL (`chr(0)`) is correctly rejected by these character classes.
- Related: when you tighten validation on an existing `/api/worker/jobs/{id}/*` callback, remember that `worker.py` reports failures through the same URL space and swallows the error (`except WorkerError: pass`) — a job whose id the new guard rejects can neither be finished nor failed, so the reaper requeues it forever. Ship a one-off cleanup for rows created while the bug was open.

## 2026-09-16 — security-engineer: BUG-044 fix audit
- **Hardening an id that a worker callback already uses strands every row already in the queue.** `worker.py` reports failure through `POST /api/worker/jobs/{id}/error` and swallows the error from *that* call, so when the server starts rejecting the id itself the job can neither finish nor fail: it stays `running`, `pgstore.jobs_reap(30)` (run from `jobs.claim()` on every worker poll) requeues it, the worker claims it again and re-runs the LLM — forever, with no `attempts` cap. Any diff that adds or tightens validation on an existing callback must answer "what about rows already in the queue?" with a claim-side reject, a detection query, and a cleanup.
- **`re.match` + `$` is not `fullmatch`**: Python's `$` also matches just before a trailing newline, so `store.valid_id("20260916-120000-abcdef" + chr(10))` is `True`. Every id/path validator in this repo is copied from that pattern (`store._ID_RE`, `pgstore._ID_RE`, and now `_JOB_SUFFIX_RE` in `server.py`). Use `re.fullmatch` or the `\Z` anchor in anything new, and test the valid value with a newline appended before believing a validation fix.
- **Proving "no file escaped" needs a diff of the data dir *and its parent***, taken before/after the run. Listing only `WEB_DIR` cannot see the exact failure mode the bug was about.

## 2026-09-16 — test-engineer: BUG-044 regression + a Windows-specific path-traversal gotcha
- **Windows resolves `..` lexically even through path segments that don't exist as real directories; POSIX does not.** `WEB_DIR / "fake_dir_that_never_existed" / ".." / ".." / "pwned.wav"` opens (and writes) successfully on this Windows box, landing one level above `WEB_DIR`'s parent — even though `fake_dir_that_never_existed` is never created on disk. On Linux, the kernel resolves path components sequentially and would fail with `ENOENT` on the missing intermediate segment before ever reaching `..`. This is *why* the BUG-044 PoC (`<mid>.tr./../../../pwned` — the `<mid>.tr.` segment is never a real directory) worked when reproduced on the owner's Windows machine: don't assume a traversal PoC that "shouldn't work" per POSIX reasoning is safe until you've checked the actual OS. Verified by temporarily monkeypatching `server._safe_job_id` back to always-`True` (simulating the pre-fix state) and watching the guarded regression test flip from blocked (400) to an actual file write with `status 200` and a `playback` path one directory above `WEB_DIR`.
- To prove a guard test is not vacuous without touching committed source: `mock.patch.object(module, "function_name", lambda *a: <old_buggy_return>)` around a fresh run of just that test (`unittest.TestSuite()` + `TextTestRunner().run(...)`), confirm it now fails for the *reason the bug describes*, then let the `with` block exit and rerun to confirm it passes again. Cheaper and safer than editing-and-reverting the real file.
- Percent-decoding order matters for tests, not just code: a wire-level payload of `%252F` becomes the *literal three characters* `%2F` after exactly one `urllib.parse.unquote()` pass (not a real `/`). A suffix allow-list regex that excludes `%` blocks this automatically — you don't need to defeat double-encoding with extra decode passes, just don't allow `%` in the charset.
