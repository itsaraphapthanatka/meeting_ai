# meeting_ai — system context for the agent team

Single source of truth for every agent in `./.claude/agents/`. Read this before touching any repo. Facts were verified on 2026-09-16 (code review + bootstrap on the owner's Windows 11 machine); when you find one that is wrong, fix it here (anyone may correct a fact; there is no tech-writer role yet, so the agent who finds the error owns the fix).

## Product in one paragraph
meeting_ai records meetings, transcribes them with whisper.cpp, separates speakers (sherpa-onnx diarization or two-track recording), and produces a **Thai** Markdown summary with an action-item table via an OpenAI-compatible LLM (default model `gemma-4-12b`). Audio comes from file upload, three browser recording modes (mic only / mic + loopback device / tab share), or a Docker "notetaker" bot that joins Google Meet or Microsoft Teams (Zoom blocks automated browsers by policy; the project deliberately does not evade it). Two deployment modes from one codebase: **local** (single user, no login, JSON files under `recordings/web/`, everything runs in one process) and **cloud** (Vercel serverless UI/API + Postgres + Cloudflare R2, teams with admin/invite-only signup, private/team visibility, share links, and a self-hosted GPU worker that pulls jobs). Core entity: a *meeting job* `draft → queued → running → done | error`, which on success becomes a *meeting* (title, audio key, `segments[]` with speaker/start/end/text, `summary` Markdown, `translations{}`). Personal data everywhere: meeting audio, transcripts, summaries, and the bot's logged-in Google/Microsoft/Zoom browser profile. No money moves. UI, prompts, comments and docs are Thai; identifiers are English.

## Architecture map
**Entry points**
- CLI: `mai` / `mai.cmd` → `python -m meeting_ai` → [meeting_ai/cli.py](../meeting_ai/cli.py) subcommands `devices, record, transcribe, summarize, process, bot, bot-login, web, db-init, worker`. Every subcommand imports its module lazily. `record`, `transcribe`, `process`, `bot` accept `--stt {local,api}` (overrides `STT_PROVIDER`; the CLI honours the provider since the P0 fix).
- Web: [meeting_ai/web/server.py](../meeting_ai/web/server.py) class `Handler` on `ThreadingHTTPServer`, bound to `127.0.0.1` by default. [api/index.py](../api/index.py) subclasses the same `Handler` for Vercel (forces `MEETING_AI_CLOUD=1`, disables the Host allow-list because Vercel routes).

**Layers (server side)** `server.py` (HTTP, auth, validation, routing) → `web/jobs.py` (queue + job state, in-process thread or remote-worker mode) → `runner.py` (the ONE processing path: `stt.transcribe` → `diarize` → `mix_tracks` → `summarizer.summarize`) → `stt.py` (local whisper.cpp via `transcriber.py`, or OpenAI-compatible `/audio/transcriptions`), `diarize.py` (sherpa-onnx, optional), `summarizer.py` (LLM, SSE streaming, 5 Thai templates, translate). `worker.py` calls the same `runner` functions from a remote GPU machine. `bot.py` (host side) + `bot/` (container side) feed `runner.bot_job`. Below both `server.py` and `jobs.py` sits `web/sanitize.py` (stdlib only, imports nothing from the project): the shared shape rules for meeting content coming from an untrusted side — finite `start`/`end`, segment/text/name caps, `duration`, `language`, `speakers`. `jobs.apply_result()` runs every worker-supplied field through it (BUG-048); `server._clean_segments()` still has its own copy of the rule (merge them once BACKLOG #11 lands).

**Storage** `web/backend.py` picks at import time: `MEETING_AI_CLOUD` truthy **and** `DATABASE_URL` set → `web/pgstore.py` (Postgres, schema `meeting_ai`, tables `users, sessions, invites, meetings, shares, jobs, workers, settings, rate_limits` in [web/schema.sql](../meeting_ai/web/schema.sql)); otherwise `web/store.py` (`recordings/web/index.json` + `<id>.json` + audio; since BUG-056 every write goes through `store._guard()` = `threading.RLock` **plus** a cross-process lock file `recordings/web/.store.lock` via `msvcrt.locking`/`fcntl.flock`, read paths stay lock-free, and `_write_json` uses a pid-suffixed tmp + retries `os.replace` on Windows sharing violations). Both expose the same function names for meetings; auth/share/job/worker functions exist **only** in `pgstore.py` and every call site is guarded by `backend.cloud` / `backend.auth_required()`. Helpers that belong to neither backend (`new_id`, `valid_id`, `fmt_time`, `transcript_text`, `timestamped`, `snippet`) live once in `web/_common.py` since BACKLOG #26 — before that the two copies had drifted and only the Postgres one tolerated `None`. Blobs: `web/blobstore.py` → `LocalStorage` (disk) or `S3Storage` (R2/S3, hand-rolled SigV4 presigned PUT/GET; the browser uploads straight to R2 because Vercel bodies cap at 4.5 MB). Blob storage is independent of the DB backend, but S3 is **never** chosen implicitly since BUG-045: `backend.storage()` calls `blobstore.get_storage(root, allow_remote=cloud)`, so file mode needs `MEETING_AI_REMOTE_BLOBS=1` to touch a real bucket; every selection logs one line at warning level (S3 → endpoint + bucket, never keys; S3_* complete but skipped → how to enable). `web/db.py`: psycopg pool, `prepare_threshold=None` for pooler transaction mode, IPv4 pinning. Expired sessions/rate limits and long-gone workers are swept by `pgstore.sweep()` (BACKLOG #24), claimed through the database clock so several instances cannot sweep at once.

**Routes** (all in `server.py`; `_route → _api → _meeting | _auth_api | _worker_api`)
- `GET /api/config` · `POST /api/live` (short clip transcription, server-side whisper only) · `POST /api/settings` (admin)
- `GET|POST /api/meetings` · `POST /api/meetings/bot` · `GET /api/jobs` · `GET /api/workers` · `GET /api/jobs/{id}` · `POST /api/jobs/{id}/stop`
- `/api/meetings/{id}/…`: `tracks/{name}/upload-url`, `tracks/{name}` (POST bytes or `?key=` confirm), `process`, `share` (GET/POST/DELETE), `visibility` (PATCH), `audio` (Range or 302 presigned), `export.{md|txt|srt|vtt|docx}`, `resummarize`, `translate`, and `GET|PATCH|DELETE` on the meeting
- `/api/auth/{me,login,signup,logout,invite}` (cloud only)
- `/api/worker/{heartbeat,claim}` · `/api/worker/jobs/{id}/{tracks/{name},progress,audio,result,error,requeue}` (Bearer `WORKER_TOKEN`)
- `GET /s/{token}` share entry — **since BUG-016 (2026-09-17, merged in `0710d5b`) it only validates the token and serves the SPA; the `mai_share` cookie is set by `POST /api/auth/share` (public, JSON-only, 415 otherwise) after the user confirms in the UI** · static under `/`, `/static/*`, `/sw.js`, `/manifest.webmanifest`, `/meeting-ai-poster.html` (the static path guard is `Path.is_relative_to`, not `str.startswith`, since BUG-015)

**Auth pattern** Local mode: none (documented). Cloud: cookie `mai_session` → `store.user_for_session` → `self.user` / `self.user_id`; scrypt passwords; invite-only signup, first user becomes admin — both are claimed with one atomic statement *before* the user row exists (`claim_invite` sets `invites.used_at`, `claim_first_admin` latches the `settings` key `signup_bootstrap`); share links are sha256-hashed tokens with optional `can_edit` + expiry, carried in cookie `mai_share`. Permission helpers `_is_owner`, `_may_read`, `_may_write`, `_may_write_job`; `PUBLIC_API` lists unauthenticated endpoints. Worker API: `Authorization: Bearer <WORKER_TOKEN>` compared with `hmac.compare_digest`, whole API disabled when the token is empty. Meeting ids match `^\d{8}-\d{6}-[0-9a-f]{6}$` (`store.valid_id`); translate job ids are `<mid>.tr.<lang>` and summaries in another language are `<mid>.sum.<lang>` (BACKLOG #9b). **P0 authz fix (2026-09-16, merged to `main` in c0b1115 via PR #1):** draft routes go through `_draft_spec(mid)` (cloud: job must have `status == "draft"`; local: `jobs._drafts`) and `_may_write_draft(spec)` (owner via `spec.owner_id`, admin override, ownerless → deny) — order `valid_id` 400 → missing 404 → foreign 403; share-only visitors pass the gate only for `_share_may_call(parts)` (GET `/api/meetings`, GET `/api/jobs`, GET `/api/jobs/{id}`, `/api/meetings/{shared id}/...`); `_job_scope()` feeds `jobs.active(owner_id=, meeting_id=)`; `_may_read_job(job)` guards `GET /api/jobs/{id}`; `_workers_view()` strips `job_title`/`job_id` for non-admins; `_may_write_job` resolves `job.get("meeting_id") or job["id"]`; summarize/translate specs carry `owner_id` (fallback: the meeting owner when a share-edit visitor submits). Since BACKLOG #37 `job_active` also shows jobs on meetings the caller can read (not only ones they submitted), and since #41 an admin's system-wide queue is flagged `mine: false` so the SPA never opens another tenant's meeting. **Auth rate limit (2026-09-17, BUG-010):** `POST /api/auth/login` and `/api/auth/signup` decide **before** `_body_json()` and before any scrypt work, through two per-IP buckets: `<scope>:<ip>` 10 per 15 min (cleared by a successful login) and `<scope>.hour:<ip>` 60 per hour (**never** cleared — the real ceiling on scrypt cost; a success-clearing bucket alone is bypassed by `9 guesses + 1 login to your own account`). Each bucket is counted twice: process-local `web/ratelimit.py` first (cheap block, survives a DB outage) then the authoritative shared counter `pgstore.rate_hit()` on table `rate_limits` (serverless instances share no memory); DB failure fails open but warns once (`server._warn_rate_db`). Over quota = 429 + `Retry-After` + `Connection: close` after draining <=64 KB of the body, one generic Thai message (no enumeration). A request with a valid `mai_session` skips the tight bucket only, so an outsider cannot lock out signed-in users behind one NAT. Client IP = `_ip_key()`: `ipaddress` parsing (drops `host:port` from Azure/IIS proxies, rejects junk), IPv6 keyed per **/64**; forwarded headers are read only when `Handler.trust_proxy` (env `TRUST_PROXY`, True in `api/index.py`) and only those listed in `Handler.forwarded_headers` — `X-Forwarded-For` for everyone, `X-Vercel-Forwarded-For` **only** in `api/index.py` because nginx/Cloudflare pass unknown headers through.

**Jobs** kinds `process | bot | summarize | translate`; local mode runs one background thread over a deque; `REMOTE_WORKER=1` makes the server a pure queue and workers claim with `UPDATE … WHERE id = (SELECT … FOR UPDATE SKIP LOCKED) … kind = any(kinds)`. Progress POSTs from the worker return `{"stop": bool}` so the stop button needs no second channel. A reaper requeues stale non-bot jobs and fails stale bot jobs (the meeting is over). `runner.HEAVY_LOCK` serializes GPU work; a worker runs at most 1 heavy job + N idle bots (`--max-bots`, default 3).

**Bot** [bot/Dockerfile](../bot/Dockerfile) = Playwright 1.48 + Chromium on Xvfb, PulseAudio `null-sink` (meeting audio) + `remap-source` virtual mic, ffmpeg records `meet.monitor` to a bind-mounted `/out` — since the P0 fix each container gets its own host dir `recordings/bot/<worker_tag>_<job id>` (`bot._job_slot`), removed only when the WAV was moved or is empty (`_stage_removable`), and `cleanup_stale()` prunes leftovers of its own worker tag except dirs of still-running containers (`_prune_stages(live=)`); [bot/platforms.py](../bot/platforms.py) holds the per-platform join steps (Meet, Teams, Zoom); the container writes `/out/bot_status.txt` (`waiting|inroom|left`) which the host polls. Login session persists in `bot/profile/` (gitignored) via a noVNC login container on `127.0.0.1:6080`. Container name `maibot_job_<worker tag>_<job id>`; image rebuilt automatically when the `mai.src` label (hash of bot sources) drifts.

**Front-end** [meeting_ai/web/static/app.js](../meeting_ai/web/static/app.js) (vanilla JS, hash routes `#new`, `#m/<id>`, `<template>` cloning), `index.html`, `style.css`, `sw.js` (network-first shell cache, never caches `/api/` or `/s/`), `manifest.webmanifest`. Transport = `fetch` + `pollJobs()` every 1.5 s while jobs are active. No i18n layer (Thai hardcoded); summary *translation* to en/ja/zh/ko is a post-processing job.

**External services** (env var **names** only): LLM `LLM_BASE_URL`/`LLM_API_KEY`/`LLM_MODEL` (OpenAI-compatible chat completions, streamed); optional STT API `STT_PROVIDER`/`STT_MODEL`/`STT_BASE_URL`/`STT_API_KEY`; whisper.cpp `WHISPER_BIN`/`WHISPER_MODEL`/`WHISPER_LANG`/`WHISPER_THREADS`/`VAD_MODEL`; `FFMPEG_BIN`, `MIC_DEVICE`, `SYSTEM_DEVICE`; queue `REMOTE_WORKER`/`WORKER_TOKEN`; cloud `MEETING_AI_CLOUD`, `DATABASE_URL`, `S3_ENDPOINT`/`S3_BUCKET`/`S3_ACCESS_KEY_ID`/`S3_SECRET_ACCESS_KEY`/`S3_REGION`, `MEETING_AI_REMOTE_BLOBS` (opt-in for real blobs outside cloud mode). Docker CLI for the bot.

## Conventions for the team
- Reports and documents addressed to the owner are written in Thai; code identifiers, paths, commands, and HTTP details stay in English. Code comments in this repo are Thai and explain *why*, often citing the incident that motivated the code; match that. Commit messages follow `feat:` / `fix:` / `chore:` in English.
- Never `git add/commit/push/stash/checkout/reset` unless the user explicitly asks in that turn. Never edit `.env` (the tracked template `.env.example` holds no values and must stay in sync), never print secret values, never add secrets to tracked files. Never touch `bot/profile/`.
- **Stdlib only** in `meeting_ai/` (the only third-party import allowed is `psycopg` inside `web/db.py` and `web/pgstore.py`; `sherpa-onnx` is optional and import-guarded in `diarize.py`). No pip dependency for the front-end either.
- Every server-side change: endpoint checks auth **and** ownership/role unless deliberately public; new `_meeting()` sub-routes go **after** the permission block (server.py ≈ lines 887-900); every filesystem path built from URL parts passes `store.valid_id()`; body size bounded; user-facing errors are Thai strings via `self._error()`.
- A `store.*` function used outside an `if backend.cloud` guard must exist in **both** `store.py` and `pgstore.py`. SQL always parameterized, tables `meeting_ai.`-qualified; schema changes are idempotent statements appended to `web/schema.sql` and applied with `./mai db-init`.
- Pipeline changes go in `runner.py` so local jobs and remote workers stay identical. Every `subprocess.run` passes `encoding="utf-8", errors="replace"`; every docker call goes through `bot._run()` with a timeout.
- Files executed inside the bot container stay **LF** (`.gitattributes` + Dockerfile CR strip). `.gitignore` ignores `*.json` globally: any new JSON that must be tracked needs an explicit `!` exception (existing: `vercel.json`, `.claude/agent-team.json`).
- Run Python through `./mai` / `.\mai.cmd` or export `PYTHONIOENCODING=utf-8`; the cp874 console otherwise crashes on Thai output.
- Documents: PRD `docs/product/PRD-<slug>.md`, ADR `docs/adr/ADR-NNN-<slug>.md`, tickets `docs/tickets/BUG-NNN-<slug>.md`, runbooks `docs/runbooks/`, QA reports `docs/qa/`, release notes `docs/releases/`, backlog `docs/product/BACKLOG.md`, team chart `docs/TEAM.md`, lessons `docs/LEARNINGS.md`.
