## ต้องแก้ก่อน (เรียงตามความรุนแรง)

### 🔴 BLOCKER 1 — เขียนไฟล์นอกโฟลเดอร์ข้อมูลได้ (arbitrary file write)
**ยืนยันแล้วด้วย PoC 2 ครั้งอิสระ** (e2e-tester + QA lead) · พบโดย api-tester และ e2e-tester ตรงกัน

เป็น **chain ของบั๊กสองตัวที่อยู่ใน BACKLOG แยกกันเป็น P1 (#13 + #14)** — เมื่อต่อกันแล้วกลายเป็น P0

1. `POST /api/meetings/{id}/translate` — [meeting_ai/web/server.py:1129-1140](../../meeting_ai/web/server.py#L1129) `_translate` เช็คแค่ `lang` ไม่ว่าง ไม่มี whitelist
2. [meeting_ai/web/jobs.py:244](../../meeting_ai/web/jobs.py#L244) `submit_translate` ประกอบ job id เป็น `f"{meeting_id}.tr.{lang}"` — `meeting_id` ผ่าน `valid_id` แล้ว แต่ `lang` ไม่ผ่าน
3. `POST /api/worker/jobs/{job_id}/audio` — [meeting_ai/web/server.py:877](../../meeting_ai/web/server.py#L877) ทำ `urllib.parse.unquote(job_id)` **หลัง** split path แล้ว และทั้งบล็อก worker API **ไม่เรียก `valid_id` เลย** จากนั้น [server.py:905](../../meeting_ai/web/server.py#L905) สร้าง `dest = store.WEB_DIR / f"{job_id}.{ext}"`

**PoC ที่ QA lead รันเอง** (sandbox ใน scratchpad, ลบทิ้งแล้ว):
```
POST /api/meetings/<mid>/translate   {"lang": "/../../../pwned_by_qa_lead"}
  -> 202  job id = "<mid>.tr./../../../pwned_by_qa_lead"
POST /api/worker/jobs/<mid>.tr.%2F..%2F..%2F..%2Fpwned_by_qa_lead/audio?ext=wav
  Authorization: Bearer <WORKER_TOKEN>
  -> 200  ไฟล์ไปโผล่ 2 ชั้นเหนือ WEB_DIR
```

**เงื่อนไขการโจมตี (สำคัญต่อการจัดลำดับ):** ต้องมี **ทั้งสองอย่าง** — สิทธิ์เรียก translate บน meeting ที่มีอยู่จริง (ผู้ใช้ที่ล็อกอินคนใดก็ได้ หรือผู้ถือลิงก์แชร์แบบแก้ไขได้) **และ** `WORKER_TOKEN`
QA lead ทดสอบยิง `%2e%2e%2f` เข้า URL ตรง ๆ โดยไม่ผ่าน translate แล้ว → ได้ **404 `ไม่พบงานนี้`** เพราะ endpoint เช็คว่า job มีอยู่จริงก่อน ดังนั้น**ต้องใช้บั๊ก translate เพื่อสร้าง job id ที่มี `../` ฝังอยู่ก่อนเสมอ** — ไม่สามารถยิงตรงจาก URL ได้
หมายเหตุ: `lang` ที่เป็น absolute path (`C:/...`) จะทำให้ `pathlib` ทิ้ง base ทั้งก้อน → เขียนได้ทุกที่ที่สิทธิ์ process เอื้อม (ไม่ได้ยิงจริง เพราะออกนอก sandbox)

**Fix (ต้องแก้ทั้งสองจุด ไม่ใช่จุดใดจุดหนึ่ง):**
- (ก) `server.py:1130` — validate `lang` ด้วย allow-list `LANGUAGE_NAMES` (หรือ regex `^[a-z]{2}(-[A-Za-z]{2})?$`) แล้วตอบ 400 ถ้าไม่ผ่าน
- (ข) `server.py:902` — ก่อนสร้าง `dest` ให้การ์ด: `Path(job_id).name != job_id` → 400 และตรวจ base ด้วย `store.valid_id(job_id.split(".tr.")[0])`

### 🔴 BLOCKER 2 — `_body_json` อ่าน body ไม่จำกัดขนาด (memory/disk DoS)
**ยืนยันแล้ว** (api-tester ยิงจริง 201; QA lead ยืนยันด้วยการอ่านโค้ด) · BACKLOG #11

[meeting_ai/web/server.py:376-385](../../meeting_ai/web/server.py#L376) — `length = int(Content-Length)` แล้ว `self.rfile.read(length)` **ไม่มีเพดานเลย** ต่างจาก `_read_body_to` ที่ใช้ `MAX_UPLOAD` (2 GB) กับการอัปโหลดไฟล์

หลักฐาน: `POST /api/meetings` body 20,000,013 ไบต์ (`{"title": "x"*20000000}`) → **201 Created**

กระทบทุก endpoint ที่เรียก `_body_json()`: `POST /api/meetings`, `POST /api/settings`, `PATCH /api/meetings/{id}`, `/translate`, `/resummarize`, worker `progress`/`result`/`error`
**Fix:** เพิ่ม `MAX_BODY` แยกจาก `MAX_UPLOAD` (256 KB–1 MB พอสำหรับ control-plane JSON) แล้วเช็คก่อน `rfile.read()` → 413

### 🟠 HIGH 3 — `_clean_segments` ไม่จำกัดจำนวน item และความยาว text
พบโดย api-tester (code review; ไม่ได้ยิงจบ end-to-end) · BACKLOG #11 แถวเดียวกับข้อ 2

[meeting_ai/web/server.py:1260-1278](../../meeting_ai/web/server.py#L1260) — `for item in raw` ไม่จำกัดจำนวน และ `text` ไม่ถูกตัด (ต่างจาก `speaker` ที่ตัดที่ 60 ตัวอักษร) root cause เดียวกับข้อ 2
**Fix:** `if len(raw) > N: return None` และ `text[:M]`

### 🟠 HIGH 4 — โหมด `files` ออก presigned URL ของบัคเก็ต R2 **production** จริง
พบโดย api-tester (เจอเข้าจริงระหว่างทดสอบ) · QA lead ยืนยันโค้ดแล้ว

[meeting_ai/web/backend.py](../../meeting_ai/web/backend.py) `storage()` เรียก `blobstore.get_storage()` ซึ่งที่ [blobstore.py:284](../../meeting_ai/web/blobstore.py#L284) เลือก `S3Storage` ทันทีที่เจอ `S3_BUCKET` ใน env — **โดยไม่สนใจ `MEETING_AI_CLOUD` เลย**

ผลจริง: รัน `./mai web --no-open` เฉย ๆ บนเครื่องที่มี `.env` → `/api/config` รายงาน `"mode": "files"` แต่ `GET .../tracks/mixed/upload-url` คืน **presigned PUT URL ที่เขียนบัคเก็ต production ได้จริง** (อายุ 1 ชม.) api-tester ไม่ได้ยิง PUT จริง ไม่มีไฟล์ถูกอัปโหลด

**ที่ต้องทำ:**
1. **แนะนำให้เจ้าของหมุนกุญแจ R2** (`S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY`) เพราะ URL ที่เซ็นด้วยกุญแจนี้ถูกพิมพ์ออกมาใน log ของเซสชัน agent แล้ว (ไม่ได้หลุดออกนอกเครื่อง)
2. แยก bucket dev/test ออกจาก production
3. พิจารณาให้ `storage()` เคารพ `MEETING_AI_CLOUD` หรืออย่างน้อยเตือนดัง ๆ เมื่อโหมด `files` แต่กำลังจะใช้ S3
4. สูตรทดสอบ "isolated" ทุกที่ต้องล้าง `S3_BUCKET S3_ENDPOINT S3_ACCESS_KEY_ID S3_SECRET_ACCESS_KEY` ก่อนเปิดเซิร์ฟเวอร์ (api-tester แก้ `docs/PROJECT-CONTEXT.md` + `docs/LEARNINGS.md` ให้แล้ว)

### 🟡 MEDIUM 5 — `Range` เกินขนาดไฟล์ตอบ 200 แทน 416
พบโดย e2e-tester (ยิงจริง)

`GET /api/meetings/{id}/audio` + `Range: bytes=99999999-` → **200** ส่งทั้งไฟล์ 160,078 ไบต์ ไม่มี `Content-Range`
[meeting_ai/web/server.py:1154-1155](../../meeting_ai/web/server.py#L1154) คืน `None` เมื่อ `start >= size` แล้ว caller ตกไปทางส่งทั้งไฟล์ · ผิด RFC 9110 §14.4 · ผลกระทบจริงต่ำ (เบราว์เซอร์ไม่ยิงแบบนี้)
**Fix:** แยกเคส "range อ่านได้แต่ไม่ครอบคลุม" → 416 + `Content-Range: bytes */<size>`

### 🟡 MEDIUM 6 — ตัวเลือก "แชร์แท็บ" ไม่ถูกซ่อนที่ mobile viewport
พบโดย web-tester

[meeting_ai/web/static/app.js:704-710](../../meeting_ai/web/static/app.js#L704), [index.html:161-167](../../meeting_ai/web/static/index.html#L161) — ควบคุมด้วย feature-detection (`navigator.mediaDevices?.getDisplayMedia`) เท่านั้น และเมื่อไม่รองรับก็แค่ `tab.disabled = true` (ยังแสดงอยู่ ไม่ใช่ `hidden`) ไม่มี media query หรือ `matchMedia` ที่ไหนเลย
ผล: ย่อ desktop browser เป็น 375px (วิธีทดสอบ mobile ทั่วไป) ตัวเลือกนี้ยังแสดงและกดได้ปกติ
**Fix:** ใช้ `window.matchMedia('(max-width: 480px)')` ควบคู่ feature-detection และเปลี่ยนเป็น `.closest('.mode').hidden = true`

## API test: PASS with warnings

### Bugs
1. **[High — ต้องมี WORKER_TOKEN] เขียนไฟล์นอกโฟลเดอร์ข้อมูลได้ (arbitrary path write)** — chain 2 จุด:
   - `POST /api/meetings/{id}/translate` body `{"lang": "/../../../escaped_by_e2e"}` → **202** และได้ job id `20260916-153748-b3a349.tr./../../../escaped_by_e2e` (`meeting_ai/web/server.py:1129-1140` `_translate` ไม่ validate `lang` เลย)
   - `POST /api/worker/jobs/<job_id url-encoded>/audio?ext=wav` (Bearer WORKER_TOKEN) → **200** `{"playback": ".../web/<mid>.tr.\\..\\..\\..\\escaped_by_e2e.wav"}` และไฟล์ไปโผล่จริงที่ `…/scratchpad/escaped_by_e2e.wav` (นอก WEB_DIR 2 ชั้น) เพราะ `meeting_ai/web/server.py:901-906` สร้าง `dest = store.WEB_DIR / f"{job_id}.{ext}"` **โดยไม่ผ่าน `store.valid_id()`** — encode `%2F` ทำให้ตัว split path ของ `_route` ไม่กินจุดสองจุดไป (แบบไม่ encode ได้ 404 จึงปลอดภัย)
   - ถ้า `lang` เป็น absolute path (`C:/...`) `pathlib` จะทิ้ง base ทั้งก้อน → เขียนได้ทุกที่ที่สิทธิ์ process เอื้อม (ไม่ได้ยิงจริงเพราะออกนอก sandbox)
   - **Fix:** (a) `server.py:1130` validate `lang` ด้วย whitelist/regex `^[a-z]{2}(-[A-Za-z]{2})?$` แล้ว 400 ถ้าไม่ผ่าน; (b) `server.py:902` เพิ่มการ์ด `base = job_id.split(".tr.")[0]; if not store.valid_id(base) or Path(job_id).name != job_id: return 400` ก่อนสร้าง `dest` (แก้ทั้งสองที่ ไม่ใช่ที่ใดที่หนึ่ง)
2. **[Low] silent success ของ `lang` ขยะ** — `translate` ตอบ 202 และเก็บลง `translations` ด้วยคีย์ `"../../pwn"` (ยืนยันจาก `GET /api/meetings/{id}` → `translation_keys=['../../pwn']`) แถมข้อความนี้ไหลเข้า prompt ของ LLM ตรงๆ (prompt injection). แก้พร้อมข้อ 1
3. **[Low] `Range` ที่เกินขนาดไฟล์ตอบ 200 ทั้งไฟล์แทน 416** — `GET /api/meetings/{id}/audio` + `Range: bytes=99999999-` → 200, 160078 bytes, ไม่มี `Content-Range` (`server.py:1154-1155` คืน `None` เมื่อ `start >= size` แล้ว caller ตกไปทางส่งทั้งไฟล์) ผลกระทบจริงต่ำ (เบราว์เซอร์ไม่ยิงแบบนี้) แต่ผิด RFC 9110 §14.4 · **Fix:** แยกเคส "range อ่านได้แต่ไม่ครอบคลุม" ให้ตอบ 416 + `Content-Range: bytes */<size>`

### Bugs

1. **`meeting_ai/web/static/app.js:704-710`, `meeting_ai/web/static/index.html:161-167`** — ตัวเลือก "แชร์แท็บ" ไม่ถูกซ่อนที่ mobile viewport ตามสเปก แต่ถูกควบคุมด้วย feature-detection (`navigator.mediaDevices?.getDisplayMedia`) เท่านั้น และเมื่อไม่รองรับก็แค่ตั้ง `tab.disabled = true` (ยังแสดงผล ไม่ใช่ `hidden`) ไม่มี CSS media query หรือ JS ตรวจ `innerWidth`/`matchMedia` เลย (grep ยืนยันว่าไม่มีคำว่า `375`, `innerWidth`, `matchMedia` ที่ไหนใน `app.js`/`style.css`)

   - **Actual**: ถ้าเบราว์เซอร์ desktop ถูกย่อหน้าต่างเป็น 375px (วิธีทดสอบ mobile viewport ทั่วไปด้วย DevTools) `getDisplayMedia` ยังมีอยู่ในเอนจิน desktop เต็มรูปแบบ — ตัวเลือกนี้จะยังคง**แสดงและกดใช้งานได้ปกติ** ไม่ถูกซ่อนหรือปิดเลย มีแค่บนมือถือจริงที่ไม่มี API นี้เท่านั้นที่จะถูก disable (แต่ไม่ hidden)
   - **Fix suggestion**: เพิ่มเงื่อนไข viewport/touch (`window.matchMedia('(max-width: 480px)')` หรือคล้ายกัน) ควบคู่กับ feature-detection และเปลี่ยนจาก `disabled` เป็น `.closest('.mode').hidden = true` เพื่อให้ตรงสเปกทั้งสองกรณี
