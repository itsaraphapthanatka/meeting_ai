# Runbook — เปิด sandbox ของ Chromium ในคอนเทนเนอร์บอท

**ทำโดย:** เจ้าของระบบ (ต้องมี Docker daemon และส่งบอทเข้าห้องประชุมจริงหนึ่งครั้ง — agent ทำแทนไม่ได้)
**เกี่ยวกับ:** BACKLOG #21b · **อัปเดต 2026-09-18**

## ทำไมต้องมีขั้นตอนนี้ แทนที่จะเปิดให้เลย

กลไกพร้อมใช้แล้ว แต่ **ค่าเริ่มต้นยังเป็นปิด** เพราะการเปิดโดยที่ host ไม่รองรับ ทำให้
Chromium **ไม่เปิดเลย** อาการที่เห็นจากหน้าเว็บคือ "บอทไม่เข้าห้อง" เฉย ๆ = ประชุมครั้งนั้น
หายไปทั้งครั้ง ซึ่งแย่กว่าความเสี่ยงที่เรากำลังลด และยืนยันได้ทางเดียวคือลองของจริง

## เรากำลังลดความเสี่ยงอะไร

บอทเปิดหน้าเว็บของคนอื่นด้วย Chromium ซึ่งเป็นพื้นผิวโจมตีที่ใหญ่ที่สุดในระบบนี้
`--no-sandbox` ปิดกำแพงชั้นที่กันไม่ให้ renderer ที่ถูกเจาะ ออกมาถึงสิ่งที่ mount เข้าไปใน
คอนเทนเนอร์ ซึ่งรวม `/prof` — **session ที่ล็อกอิน Google ของบอท**

คอนเทนเนอร์ไม่ได้รันเป็น root แล้วตั้งแต่ #21 ชั้นนี้คือชั้นถัดไป ไม่ใช่ชั้นเดียวที่มี

## เลือกทางใดทางหนึ่ง

| ทาง | ตั้งค่า | ข้อดี / ข้อเสีย |
|---|---|---|
| **seccomp profile** | `MAI_BOT_SECCOMP=/path/chrome.json` | แคบกว่ามาก ให้เฉพาะ syscall ที่ sandbox ต้องใช้ · ต้องหาไฟล์โปรไฟล์มาเอง |
| **capability** | `MAI_BOT_SANDBOX=1` | ไม่ต้องมีไฟล์อะไร · `SYS_ADMIN` กว้างกว่าที่จำเป็นมาก |

ตั้งทั้งสองอย่าง = ใช้ทาง seccomp และ **ไม่** ใส่ `SYS_ADMIN` (ใส่ทั้งคู่คือคืนสิทธิ์ที่เพิ่งตัดไป)

## ขั้นตอน

1. ตั้งค่าใน `.env` ของเครื่อง worker (เครื่องที่มี Docker) — ไม่ใช่บน Vercel
   ```bash
   MAI_BOT_SANDBOX=1
   ```
2. รีสตาร์ต worker ให้อ่านค่าใหม่
   ```bash
   sudo systemctl restart meeting-ai-worker     # Linux
   ```
   ```powershell
   .\worker-service.ps1 restart                 # Windows
   ```
3. **ทดสอบด้วยห้องประชุมของตัวเองก่อน** ห้ามทดสอบกับประชุมจริงที่มีคนอื่น
   ```bash
   ./mai bot "<ลิงก์ห้องทดสอบของคุณ>" --title "ทดสอบ sandbox"
   ```

## อะไรคือ "ผ่าน"

- มีบรรทัด `[bot] ...` ไหลออกมาตามปกติ และบอทโผล่ในห้องให้กด Admit
- ได้ไฟล์ `.wav` ที่ขนาดไม่ใช่ศูนย์เมื่อจบ

## อะไรคือ "ไม่ผ่าน" และทำอย่างไรต่อ

อาการ: บอทไม่โผล่ในห้องเลย และ log มีบรรทัดจาก Chromium ทำนอง
`Failed to move to new namespace` / `No usable sandbox!` / `Operation not permitted`

ถ้าเจอแบบนั้น:

1. กลับค่าเดิมทันที — `MAI_BOT_SANDBOX=0` แล้วรีสตาร์ต worker (บอทจะกลับมาทำงานเหมือนเดิม)
2. ลองทาง seccomp แทน: หาไฟล์โปรไฟล์ของ Chromium มาวางไว้ แล้วตั้ง `MAI_BOT_SECCOMP`
   ชี้ไปที่ไฟล์นั้น (ไฟล์ต้องมีอยู่จริง ไม่งั้นระบบจะฟ้องตั้งแต่ก่อนเรียก docker)
3. บันทึกผลลงแถว #21b ในแบ็กล็อก ว่าเครื่องนี้ใช้ทางไหนได้/ไม่ได้

## ตรวจว่าค่ามีผลจริงโดยไม่ต้องเข้าห้อง

คำสั่งนี้ไม่พิสูจน์ว่า sandbox ทำงาน (ต้องเข้าห้องจริงเท่านั้น) แต่ยืนยันว่าค่าถูกอ่านและ
ธงถูกประกอบเข้าคำสั่ง `docker run`:

```bash
python -c "from meeting_ai import bot; print(bot._sandbox_flags())"
```

ปิดอยู่จะได้ `[]` · เปิดแล้วจะได้ `['--cap-add=SYS_ADMIN', '-e', 'CHROMIUM_SANDBOX=1']`
