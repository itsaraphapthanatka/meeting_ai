## สิ่งที่อยู่ใน `.env` และแต่ละตัวทำอะไรได้ถ้าหลุด

| ตัวแปร | ถ้าคนอื่นได้ไป |
|---|---|
| `DATABASE_URL` | อ่าน/เขียน/ลบฐานข้อมูล production ทั้งหมด — บทถอดเสียง สรุป บัญชีผู้ใช้ |
| `S3_ACCESS_KEY_ID` · `S3_SECRET_ACCESS_KEY` | อ่าน/เขียน/ลบไฟล์เสียงทั้งบัคเก็ต |
| `VERCEL_TOKEN` | deploy ทับโปรเจกต์ อ่าน/แก้ env vars ซึ่งหมายถึงได้ค่าอื่นทั้งหมดต่อ |
| `WORKER_TOKEN` | เรียก `/api/worker/*` ได้ทั้งชุด รวมอัปโหลดผลลัพธ์ปลอม |
| `LLM_API_KEY` · `STT_API_KEY` | ใช้โควตาของคุณ คิดเงินเข้าบัญชีคุณ |

## ลำดับการหมุน

เรียงตามความเสียหายถ้าถูกใช้ก่อน

**1. `VERCEL_TOKEN`** — หมุนก่อนเพื่อน เพราะตัวนี้เป็นกุญแจไปสู่ตัวอื่นทั้งหมด (อ่าน env vars ของโปรเจกต์ได้)
Vercel → Account Settings → Tokens → เพิกถอนตัวเก่า สร้างใหม่ → อัปเดต `.env`

**2. `DATABASE_URL`** — Neon/Supabase → รีเซ็ตรหัสผ่านของ role หรือสร้าง role ใหม่
อัปเดตที่ **Vercel env vars** แล้ว **redeploy** จากนั้นอัปเดต `.env`
ตรวจว่าเว็บยังล็อกอินและเปิดรายการประชุมได้ ก่อนเพิกถอนของเก่า

**3. คีย์ R2** — Cloudflare → R2 → Manage API Tokens → สร้างใหม่แบบ **Object Read & Write จำกัดเฉพาะบัคเก็ตที่ใช้**
อัปเดต Vercel → **redeploy** → ทดสอบอัปโหลดจริงหนึ่งรายการ → แล้วค่อยเพิกถอนตัวเก่า
⚠️ ถ้าเพิกถอนก่อนทดสอบ ระบบอัปโหลดจะล่มทั้งตัว

**4. `WORKER_TOKEN`** — เป็นค่าที่คุณกำหนดเอง ตั้งใหม่ให้ตรงกันทั้งสองฝั่ง
Vercel env vars **และ** `.env` ของทุกเครื่อง worker (1346 และเครื่องอื่นถ้ามี) แล้วรีสตาร์ต worker
worker กับเซิร์ฟเวอร์ต้องตรงกัน ไม่งั้นงานจะค้างคิว

**5. `LLM_API_KEY` · `STT_API_KEY`** — หมุนที่ผู้ให้บริการ อัปเดต Vercel + `.env` + เครื่อง worker

## หลังหมุนเสร็จ ตรวจสามอย่าง

1. **บัคเก็ต R2** — มีไฟล์แปลกปลอมช่วง 2026-09-16 เป็นต้นมาไหม
2. **ฐานข้อมูล** — บัญชีผู้ใช้ที่ไม่รู้จัก หรือ session ที่ไม่ควรมี
3. **Vercel** — deployment ที่ไม่ได้มาจากคุณ

## กันไม่ให้เกิดซ้ำ

- **อย่าคัดลอก `.env` ไปเครื่องที่ใช้ร่วมกับคนอื่นหรือกับ CI runner** ถ้าจำเป็นต้องรันคำสั่งที่ใช้ credential บนเครื่องอื่น ให้ป้อนเฉพาะค่าที่ต้องใช้ผ่าน `read -rs` (ไม่เข้า shell history ไม่เขียนลงดิสก์ หายไปเมื่อปิด session) แทนการยกไฟล์ไปทั้งไฟล์
- **แยกไฟล์ตามหน้าที่** — `.env` ของ worker ไม่ต้องมี `DATABASE_URL`, คีย์ R2 หรือ `VERCEL_TOKEN` เลย (`setup-worker.ps1` เขียนไว้ถูกแล้วว่า worker ไม่ต้องใช้)
- **แยก bucket และฐานข้อมูล dev ออกจาก production** เพื่อให้การทดสอบที่พลาดไม่แตะของจริง
- ทุกครั้งที่เปิดเซิร์ฟเวอร์ทดสอบ ให้ล้าง `S3_BUCKET S3_ENDPOINT S3_ACCESS_KEY_ID S3_SECRET_ACCESS_KEY` ก่อน (`tests/_harness.py` ล้างให้อัตโนมัติแล้ว)

## สิ่งที่ตรวจแล้วและไม่ต้องกังวล

- **ไม่มี credential อยู่ใน git** — `.env` ไม่เคยถูก track และไม่เคยอยู่ใน history ไฟล์ตระกูล `.env*` ที่เคยเข้า git มีแค่ `.env.example` ซึ่งบรรทัดค่าลับถูกคอมเมนต์และว่างเปล่า **ไม่ต้องล้าง git history**
- ไม่มีค่าลับ hardcode ในโค้ด ทุกจุดอ่านจาก `os.environ`
- CORS ของบัคเก็ตเป็นคนละเรื่องกับกุญแจ ไม่ต้องแก้
