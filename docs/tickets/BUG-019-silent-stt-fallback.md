# BUG-019 — `stt.resolve()` ตกจาก local ไป API เงียบ ๆ (เสียงประชุมออกนอกเครื่องโดยไม่มีใครสั่ง)

- **Severity:** P1 (BACKLOG #19) — ความเป็นส่วนตัวของข้อมูลผู้ใช้ ไม่ใช่บั๊กที่ผู้ใช้เห็นเป็น error
- **Owner:** backend-dev (verify: test-engineer, security-engineer)
- **Status:** **fixed (uncommitted)** 2026-09-17
- **Source:** BACKLOG #19 · แพตเทิร์นเดียวกับ [BUG-045](BUG-045-implicit-remote-blob-storage.md) (ที่เก็บไฟล์ของจริงถูกเปิดเองเงียบ ๆ)

## เกิดอะไรขึ้น

[meeting_ai/stt.py:110-122](../../meeting_ai/stt.py#L110) (ก่อนแก้):

```python
def resolve(name: str | None) -> str:
    avail = providers()
    want = (name or config.stt_provider or LOCAL).strip().lower()
    if want in avail and avail[want]["available"]:
        return want
    for other, info in avail.items():
        if info["available"]:
            return other        # <- เลือกอีกตัวให้เองเงียบ ๆ
    raise RuntimeError(...)
```

ขอ `local` แล้วเครื่องไม่มี `whisper-cli` หรือไม่มีไฟล์โมเดล (ย้ายโมเดล / ติดตั้งไม่ครบ / path ผิด /
worker เพิ่งอัปเดตแล้ว binary หาย) → คืน `api` → [stt.transcribe()](../../meeting_ai/stt.py) **อัปโหลดไฟล์เสียงประชุมทั้งไฟล์**
ไปที่ `STT_BASE_URL` (ว่าง = `LLM_BASE_URL`) โดยไม่มีบรรทัดแจ้ง ไม่มี error ไม่มีอะไรในหน้าเว็บ

สำหรับผลิตภัณฑ์ที่ขายเรื่อง "อัดประชุมส่วนตัว" การที่เสียงออกจากเครื่องโดยไม่มีใครสั่ง คือสิ่งที่ห้ามเกิดโดยอุบัติเหตุ
(`providers()[LOCAL]["note"]` เขียนไว้เองว่า "เสียงไม่ออกไปที่อื่น" — คำสัญญานี้ผิดทันทีที่ fallback ทำงาน)

## สองทิศทางไม่เท่ากัน

| ทิศทาง | ผล | ระดับ |
|---|---|---|
| local → api | เสียงออกจากเครื่องไปที่บุคคลที่สาม + เสียเงิน | **อันตราย** |
| api → local | เสียงอยู่กับเครื่อง แค่ช้าลง | ไม่อันตราย แต่ควรบอก |

## "ขอ local" ไม่ได้มีความหมายเดียว — จุดที่ต้องตัดสินใจ

`resolve(name)` รับค่าจากสามชั้น: `name` → `config.stt_provider` → ค่าคงที่ `LOCAL`
แต่ `config.stt_provider` = `_get("STT_PROVIDER", "local")` **มีค่าเป็น `"local"` เสมอแม้ไม่มีใครตั้ง**
โค้ดเดิมจึงแยกไม่ออกว่า "คนสั่ง local" หรือ "ไม่มีใครตั้งอะไรเลย"

บน Vercel/เครื่องที่ไม่มี whisper และไม่ได้ตั้ง `STT_PROVIDER` การไปใช้ `api` คือเส้นทางปกติที่ถูกต้อง
ถ้าทำให้เคสนั้นเป็น error การถอดเสียงบน cloud จะพังทั้งระบบ **การแก้จึงต้องแยกสองเคสนี้ออกจากกัน**

**วิธีแยกที่เลือก:** เพิ่ม `config.stt_provider_set` = `bool(os.environ["STT_PROVIDER"])` (ว่าง/ไม่มี = `False`)
แล้วนิยาม

- **"เลือกเอง" (explicit)** = ผู้เรียกส่ง `name` มา (`--stt local` จาก CLI หรือ `{"stt": "local"}` จาก dropdown ในหน้าเว็บ)
  **หรือ** มี `STT_PROVIDER` อยู่ใน environment/`.env` จริง ๆ
- **"ค่าเริ่มต้น" (default)** = ไม่มีทั้งสองอย่าง → ได้ `local` มาเพราะค่าคงที่ในโค้ด ไม่ใช่เพราะใครตัดสินใจ

`STT_PROVIDER=local` นับเป็น "เลือกเอง" เพราะมีคนพิมพ์คำว่า local ลง `.env`/dashboard เอง — ถือเป็นคำสั่ง
"ห้ามส่งเสียงออก" ผลคือเครื่องที่ตั้งค่านี้ไว้แล้ว whisper พัง งานจะ **error ให้เห็น** แทนการอัปโหลดเงียบ ๆ
ซึ่งเป็นพฤติกรรมที่ตั๋วนี้ต้องการ ส่วน Vercel/worker ที่ตั้งใจใช้ API ให้ตั้ง `STT_PROVIDER=api` (หรือไม่ตั้งเลยก็ยังใช้ได้)

ทางเลือกอื่นที่พิจารณาแล้วไม่เอา:
1. *บังคับ opt-in ด้วยตัวแปรใหม่ (เช่น `MEETING_AI_ALLOW_STT_UPLOAD=1`) แบบ BUG-045* — ทำให้ deployment บน Vercel
   ที่ใช้งานอยู่พังทันทีจนกว่าจะไปเพิ่ม env ใหม่ และ BUG-045 ต่างกันตรงที่ "ค่าเริ่มต้นเดิม" ของมันคือดิสก์ในเครื่อง
   ส่วนของเราค่าเริ่มต้นเดิมคือ API จริง ๆ บน cloud
2. *ห้าม fallback ทุกกรณี* — หยุดการถอดเสียงบน cloud ทั้งหมด ตั๋วห้ามไว้ชัดเจน
3. *เตือนอย่างเดียว ไม่ error* — ยังปล่อยให้เสียงออกจากเครื่องสวนคำสั่งที่ผู้ใช้เลือกเอง ไม่แก้ปัญหาหลัก

## สิ่งที่ต้องทำ

1. `resolve()` ต้องไม่ตกจาก **local ที่ถูกเลือกเอง** ไป `api` เด็ดขาด → `RuntimeError` ภาษาไทยที่บอก
   (ก) ทำไม local ใช้ไม่ได้ (ข) ปลายทางที่จะถูกส่งไปถ้ายอม (ค) วิธีสั่งให้ส่งจริง ๆ (`--stt api` / `STT_PROVIDER=api`)
2. เคส default (ไม่มีใครตั้งอะไร) ยัง fallback ไป `api` ได้ตามเดิม **แต่ต้องพิมพ์บรรทัดเตือนที่ระบุปลายทาง (host + โมเดล)**
3. ทุกครั้งที่ผลลัพธ์คือ `api` ต้องมีบรรทัดบอกว่าเสียงจะถูกอัปโหลดไปที่ไหน — รวมถึงตอนที่ผู้ใช้สั่ง `api` เอง
4. `api` → `local` ยัง fallback ได้ (ไม่อันตราย) แต่ต้องบอกด้วยหนึ่งบรรทัดว่าเปลี่ยนตัวแล้วเพราะอะไร
5. ไม่มีตัวไหนใช้ได้เลย → ยัง `RuntimeError` พร้อมเหตุผลของทั้งสองตัวเหมือนเดิม
6. บรรทัดแจ้งต้องไม่ทำให้ผู้เรียกพัง (คอนโซล cp874 เขียนภาษาไทยไม่ได้ / stderr ถูกปิดใน serverless) — ใช้แพตเทิร์น
   `blobstore._notice()`
7. ห้ามพิมพ์ `STT_API_KEY`/`LLM_API_KEY` ลง log

## Acceptance criteria

1. ขอ `local` เอง (`--stt local` หรือ `STT_PROVIDER=local`) + ไม่มี whisper/โมเดล + มีคีย์ API → **RuntimeError** ไม่มีการเรียก `_transcribe_api`/`urlopen` เลย
2. ไม่ได้ตั้ง `STT_PROVIDER` + ไม่มี whisper + มีคีย์ API (เส้นทางบน Vercel/worker) → คืน `"api"` ตามเดิม **และ** มีบรรทัดเตือน 1 บรรทัดที่มีชื่อ host ปลายทางอยู่ในนั้น
3. ขอ `api` เอง + มีคีย์ → คืน `"api"` และมีบรรทัดที่ระบุ host + โมเดล
4. ขอ `api` แต่ไม่มีคีย์ + มี whisper → คืน `"local"` พร้อมบรรทัดแจ้งว่าเปลี่ยนตัว
5. ไม่มีตัวไหนใช้ได้ → `RuntimeError` ที่รวมเหตุผลของทั้งสองตัว
6. ข้อความทุกอันเป็นภาษาไทย ไม่มีค่าคีย์ปรากฏ และพิมพ์ผ่านกลไกที่ไม่โยน `UnicodeEncodeError` บนคอนโซล cp874
7. ชุดทดสอบเดิมยังผ่านครบ (baseline branch นี้ = 264 tests, skipped 7)
