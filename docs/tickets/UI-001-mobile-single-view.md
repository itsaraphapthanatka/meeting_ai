## โจทย์

เจ้าของโปรเจกต์ส่งสกรีนช็อตหน้าเว็บบนมือถือมาพร้อมคำว่า "design ห่วยมาก" — และถูก

ของเดิมที่ `@media (max-width: 860px)` ทำคือ **ยุบสองคอลัมน์ให้เหลือหนึ่ง** เท่านั้น ผลคือ
sidebar ทั้งก้อน (ค้นหา + คิวงาน + รายชื่อเครื่องประมวลผล + รายการประชุม) ไปกองทับฟอร์ม
"ประชุมใหม่" ที่กางการ์ดสามใบ (อัปโหลด / อัดสด / เชิญบอท) พร้อมกันอยู่แล้ว อาการที่วัดได้:

- หน้า "ประชุมใหม่" สูง **2,449px = 3.0 เท่าของความสูงจอ** ก่อนจะเจอสิ่งที่ผู้ใช้มาทำ
  (วัดจริงที่ viewport 375×812 โหมดไฟล์ มีข้อมูล 3 การประชุม และ**ไม่มี**รายชื่อเครื่อง
  ประมวลผลด้วยซ้ำ — ของเจ้าของเครื่องมีเครื่อง 4 ตัวจึงยาวกว่านี้อีก)
- `NVIDIA GB10 / RTX 3050 / DESKTOP-S8J37O3` อยู่บนสุดของหน้าจอ — ข้อมูลของ ops ไม่ใช่ของผู้ใช้
- กล่องเทาน้ำหนักเท่ากันทุกใบ ไม่มีอะไรบอกว่าควรมองอะไรก่อน
- หน้ารายละเอียดมีปุ่มเรียงแนวนอน 12 ปุ่มใน 3 แถวบนจอกว้าง 390px
- ตัวเลือกห้าช่อง (ภาษา/รูปแบบสรุป/ตัวถอดเสียง/แยกผู้พูด/จำนวนคน) กินความสูงเกือบเต็มจอ
  ก่อนจะได้เห็นด้วยซ้ำว่าจะเอาเสียงเข้าระบบยังไง

**สิ่งที่ไม่ใช่ปัญหา:** โทเคนสีกับฟอนต์ใน `style.css` ทำไว้ดีแล้ว (Sarabun มาก่อน SF Pro
เพราะ SF Pro ไม่มีตัวอักษรไทย, `line-height: 1.65` รับสระซ้อนสามชั้น, `--rec-strong`
ผสมดำ 20% ให้คอนทราสต์ผ่าน WCAG AA) ตั๋วนี้จึงไม่แตะสีหรือฟอนต์เลยแม้แต่ค่าเดียว
— ปัญหาคือ**โครงข้อมูลของหน้า** ไม่ใช่การตกแต่ง

## สิ่งที่ทำ

### 1. จอแคบ = โชว์ทีละหน้า (`body[data-view]`)

`setView()` ตั้ง `body[data-view]` เป็น `home` / `new` / `devices` / `meeting` แล้ว CSS
เลือกว่าจะโชว์ region ไหน เส้นทางใหม่คือ `#home` และ `#devices` (ของเดิมมีแค่ `#new`
กับ `#m/<id>`) **เดสก์ท็อปไม่สนใจค่านี้เลย** — sidebar กับ panel ยังเห็นพร้อมกันเหมือนเดิมทุกอย่าง

- หน้าแรกบนมือถือ = รายการประชุม + ปุ่มหลักใบใหญ่ + ชิป `● 3 เครื่องพร้อม`
- รายชื่อเครื่องประมวลผลย้ายไปหน้า `#devices` หลังชิปนั้น
- แถบ `#mobilebar` (‹ + ชื่อหน้า + ⋯) โผล่เฉพาะหน้าที่ไม่ใช่หน้าแรก และ `.topbar`
  ซ่อนในหน้าเหล่านั้น — **หนึ่งหน้าจอมีแถบหัวเดียว** ไม่ใช่สองแถบซ้อนกินความสูง 110px
- หน้าแรกบนมือถือไม่กระโดดเข้าการประชุมล่าสุดให้เองแล้ว (เดสก์ท็อปยังทำเหมือนเดิม
  เพราะเห็นรายการอยู่ข้าง ๆ ตลอด)

### 2. ฟอร์มประชุมใหม่: เลือกวิธีทีละอัน + ยุบตัวเลือก

- `#cap-seg` เป็น segmented control (อัปโหลดไฟล์ / อัดสด / ส่งบอท) โชว์การ์ดเดียวต่อครั้ง
  ปุ่มของการ์ดที่แอดมินปิดไว้ (`#rec-card[hidden]`) จะหายไปด้วย ไม่ใช่กดแล้วเจอที่ว่าง
  และถ้าเหลือทางเดียวจะไม่โชว์ปุ่มเลย
- ห้าช่องตัวเลือกย้ายเข้า `<details class="adv">` พร้อมสรุปค่าปัจจุบันบนหัวข้อ
  (`ไทย · ประชุมทั่วไป · ในเครื่อง · แยกผู้พูด`) — **จอกว้างเปิดกางไว้เหมือนเดิม** (ตั้งจาก JS)
- แถบอัดลอยด้านล่างโผล่เฉพาะตอนอยู่แท็บ "อัดสด" (`body.cap-rec`)
- **ไม่ใช้ attribute `hidden` เป็นตัวบอกว่า "ไม่ได้เลือกแท็บนี้"** เพราะการ์ดอัดสดใช้
  `hidden` สื่อว่า "แอดมินปิดฟีเจอร์" อยู่แล้ว สองความหมายทับกันจะหาบั๊กไม่เจอ — ใช้คลาส
  `.cap-off` แยกต่างหาก

### 3. หน้ารายละเอียด: แท็บ + action sheet

- สรุปกับบทถอดเสียงกลายเป็นแท็บ (`.dtab` + `#d-seg`) — ของเดิมต้องเลื่อนผ่านสรุปทั้งอัน
  กว่าจะถึงบทถอดเสียง · จอกว้างยังต่อกันเหมือนเดิม
- ปุ่มชุด `.detail-actions` ย้ายลงเป็นแผ่นล่างจอเมื่อกด ⋯ — **ทำด้วย CSS ล้วน**
  (`body.sheet-open .detail-actions { position: fixed; bottom: 0; … }`) ไม่ได้สร้างปุ่มชุดใหม่
  ตัวจัดการเหตุการณ์ทั้งหมดจึงเป็นของเดิม ไม่มีสองชุดให้ซิงก์สถานะ `hidden`/`disabled` กันเอง
- ชื่อการประชุมไม่ขึ้นบน `#mobilebar` เพราะชื่อในเนื้อหาแก้ไขได้ (`contenteditable`)
  มีสองที่จะสับสนว่าต้องแก้อันไหน

## สองบั๊กที่เจอระหว่างทำ (บันทึกไว้เพราะจะเกิดซ้ำได้)

1. **`#d-title` มี `flex: 1 1 320px`** ซึ่งเขียนไว้สำหรับแถวแนวนอน พอ `.detail-head`
   เปลี่ยนเป็น `flex-direction: column` บนมือถือ `flex-basis` กลายเป็น **ความสูง** ทันที
   → ช่องว่างใต้ชื่อการประชุม 320px แก้ด้วย `.detail-head #d-title { flex: 0 0 auto }`
2. **กฎของจอแคบต้องอยู่ท้ายไฟล์ `style.css` เสมอ** — ตอนแรกเขียนไว้กลางไฟล์ (ตรงที่
   media query เดิมอยู่) กฎเดิมที่ specificity เท่ากันแต่เขียนทีหลังชนะด้วย source order
   เงียบ ๆ (`.detail-actions { display: none }` ไม่ทำงาน, `.list li` ได้ radius ผิด)
   ตอนนี้ย้ายไปท้ายไฟล์พร้อมคอมเมนต์เตือนแล้ว
